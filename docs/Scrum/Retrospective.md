# Retrospective – Mi Formación CTMA

## Sprint

Sprint de implementación y validación de las funcionalidades principales.

## ¿Qué salió bien?

- Se logró implementar las funcionalidades principales de la aplicación.
- Se organizaron las reglas de negocio de manera independiente de la interfaz.
- Se realizaron pruebas para validar las reglas implementadas.
- La aplicación puede ejecutarse correctamente en el emulador.
- Se verificó que el proyecto compile correctamente.
- Se organizó el trabajo utilizando historias de usuario y tareas.
- Se utilizó Git para registrar los cambios realizados.

## ¿Qué se puede mejorar?

- Ampliar la cantidad de pruebas instrumentadas para validar más funcionalidades directamente desde la interfaz.
- Mejorar progresivamente la documentación de las pruebas.
- Mantener una relación más detallada entre historias de usuario, casos de prueba y defectos.
- Continuar mejorando la organización del trabajo mediante Issues y Pull Requests.
- Revisar periódicamente la calidad del código y las configuraciones del proyecto.

## ¿Qué acciones se realizarán?

- Completar y mantener actualizados los casos de prueba.
- Registrar los defectos encontrados durante las pruebas.
- Mantener actualizada la matriz de trazabilidad.
- Relacionar los cambios de código con las historias de usuario correspondientes.
- Ejecutar las pruebas después de realizar cambios importantes.
- Mantener el repositorio organizado y actualizado.

## Conclusión

El Sprint permitió consolidar las funcionalidades principales de Mi Formación CTMA y establecer una base para continuar mejorando el producto, las pruebas y la trazabilidad del desarrollo.
